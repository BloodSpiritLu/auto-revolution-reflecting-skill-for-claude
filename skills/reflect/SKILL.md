# Reflect Skill - 自我进化系统

当用户输入 `/reflect` 时，执行以下工作流程：

## 工作流程

### 1. 扫描对话历史

回顾整个对话，识别以下类型的用户反馈：
- 明确的纠正："不要这样做"、"以后要..."
- 偏好声明："我喜欢..."、"我更倾向于..."
- 规则声明："所有的...都必须..."、"永远不要..."
- 满意/不满意的表达

### 2. 置信度分类

| 置信度 | 触发条件 | 处理方式 |
|--------|----------|----------|
| **高** | 用户明确声明的规则或禁止项 | 直接写入技能文件 |
| **中** | 本次会话中成功的实践模式 | 标记为"待确认"写入 |
| **低** | 可能的偏好趋势 | 标记为"待观察"写入 |

### 3. 作用域判断

| 作用域 | 判断标准 | 存储位置 |
|--------|----------|----------|
| **全局** | 与具体技术栈/项目无关的通用规则 | `~/.claude/skills/` |
| **项目** | 涉及特定框架、路径、架构、业务逻辑 | `./.claude/skills/` |

**判断规则**：
- 提到具体框架/库名称 → 项目级
- 提到具体文件路径/目录结构 → 项目级
- 提到具体业务逻辑/功能 → 项目级
- 通用的代码风格/沟通习惯/安全规范 → 全局
- 不确定时 → 默认项目级（避免污染全局）

### 4. 目标技能文件

**全局**（`~/.claude/skills/`）：
- `general_preferences/SKILL.md` - 通用偏好
- `coding_standards/SKILL.md` - 通用代码规范

**项目级**（`./.claude/skills/`）：
- `project_standards/SKILL.md` - 项目特定规范
- `tech_stack/SKILL.md` - 技术栈相关

### 5. 输出格式

```
## 反射结果

### 全局规则 → ~/.claude/skills/

#### general_preferences
- [高置信度] 使用中文交流

### 项目规则 → ./.claude/skills/

#### project_standards
- [高置信度] 所有表单必须包含 CSRF token

---
是否确认更新？
- [y] 全部确认
- [n] 全部取消
- [g] 只更新全局规则
- [p] 只更新项目规则
- [e] 逐条编辑
```

### 6. 执行更新

确认后：
1. 更新对应的 SKILL.md 文件
2. 如果在 Git 仓库中，执行 commit
3. commit 信息格式：`reflect: [作用域] [简要描述]`

## 注意事项

- **避免过度学习**：不要把一次性的尝试当成永久规则
- **用户优先**：始终等待用户确认后再写入
- **默认项目级**：不确定作用域时，默认放项目级
- **合并重复**：如果新规则与现有规则冲突，提示用户选择
